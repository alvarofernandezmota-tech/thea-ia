### 3.2 Análisis Profundo: Conversacional Puro vs Comandos

**PROBLEMAS CONVERSACIONAL PURO AHORA:**

❌ PROBLEMA 1: LLM es PROBABILÍSTICO
Usuario: "quiero agendar mañana a las 3"

Groq puede interpretar:
✅ "mañana" = 20 Dic 2025 (correcto)
❌ "mañana" = 20 Dic 2024 (error de año)
❌ "3" = 03:00 AM (madrugada)
❌ "3" = slot de 3 horas de duración
❌ No detecta que es un agendamiento

Success rate: ~70-80% en mejor caso

❌ PROBLEMA 2: Context Window Limitado
Conversaciones largas pierden contexto inicial

LLM olvida parámetros previos

Estado conversacional no persiste

Necesita session management (H10)

❌ PROBLEMA 3: Tool Calling Inconsistente
70% de las veces funciona correctamente

30% llama tool incorrecto o con params erróneos

Frustración del usuario cuando falla

Difícil de debugear

❌ PROBLEMA 4: Tests Nightmare
Mockear LLM responses es complejo

String matching es frágil (LLM cambia wording)

Tests fallan aleatoriamente

No puedes predecir respuesta exacta

text

**VENTAJAS COMANDOS:**
✅ VENTAJA 1: Predecible
/agendar → SIEMPRE inicia flujo de agendamiento
Success rate: 99%+

✅ VENTAJA 2: Testeable
Tests son simples y determinísticos
No dependen de LLM responses
Coverage fácil de lograr

✅ VENTAJA 3: UX Clara
Usuario sabe exactamente qué hacer
Botones guían el flujo
No hay ambigüedad

✅ VENTAJA 4: Base Sólida
Sistema funciona 100% confiable
Conversacional se añade DESPUÉS como mejora
No como reemplazo
